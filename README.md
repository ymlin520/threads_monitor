# Threads 監測系統（threads_monitor）

在自己電腦上跑的 Threads（脆）輿情與帳號分析系統。系統會自動開 Chrome 讀取 Threads 的公開頁面，把指定關鍵字、主題標籤與帳號的貼文、互動數、瀏覽數、留言與粉絲數存進本機資料庫，再用網頁儀表板呈現分析結果。

- **前台（分析）**：總覽、負面留言板、主題監測、主題交叉比較、貼文成效、瀏覽分析、帳號比較、最佳發文時段、內容成功模式
- **後台（管理）**：監測設定、立即爬文、抓取與排程、成員、系統設定
- **輿情**：自動判斷留言正負面，負面留言板用多重訊號把可能負面的留言分高／中／低三級全部列出
- **團隊**：多個工作區、帳號密碼登入（可記住我、瀏覽器自動登入）、成員角色（管理員／編輯／檢視者）
- **報表**：一鍵匯出多工作表 Excel，貼文列表、負面留言板可另存 CSV
- **自動化**：每日排程抓取、每天 17:00 自動把程式碼推上 GitHub

不需要 Threads 官方 API、不需要 Threads 帳號、不需要任何雲端服務，所有資料都在本機的一個 SQLite 檔案裡。需要讓外部的人連線時，可以用 Cloudflare 臨時網址。

## 系統需求

| 項目 | 需求 |
|---|---|
| 作業系統 | Windows 10/11、macOS、Linux（開發與實測在 Windows 11） |
| Node.js | **22.13 以上**（使用 Node 內建的 `node:sqlite`，不需另外安裝資料庫） |
| 瀏覽器 | 系統已安裝 **Google Chrome** 或 **Microsoft Edge**（爬蟲直接用系統瀏覽器，不另外下載 Chromium） |
| 網路 | 可以連到 `https://www.threads.com` |
| 選用 | [cloudflared](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/)（對外分享網址用）、[GitHub CLI](https://cli.github.com/)（自動推送用） |

確認 Node 版本：

```bash
node -v
```

## 安裝與啟動

```bash
git clone https://github.com/ymlin520/threads_monitor.git
cd threads_monitor
npm install
npm start
```

啟動後終端機會顯示：

```
Threads 監測系統已啟動：http://127.0.0.1:3900
```

用瀏覽器打開 http://127.0.0.1:3900 。

| 指令 | 用途 |
|---|---|
| `npm start` | 啟動網頁伺服器（含每日排程） |
| `npm run crawl` | 不開網頁，直接在終端機抓一次（適合搭配 Windows 工作排程器或 cron） |
| `node scripts/auto-push.mjs` | 手動把程式碼變更 commit 並推上 GitHub（`--dry-run` 只檢查） |

> 伺服器要一直開著，排程才會執行。電腦關機或伺服器關閉時，那一次排程會直接略過，不會補跑。要長時間在背景跑，見[背景執行與開機啟動](#背景執行與開機啟動)。

更新程式碼後（`git pull`），只要重新啟動伺服器即可；資料庫在啟動時會自動補上新欄位。

## 第一次使用

1. **建立系統擁有者**：第一次打開網頁會出現「建立管理員帳號」，輸入帳號、顯示名稱、密碼（至少 8 字元）與第一個工作區名稱。這個帳號是系統擁有者，可以管理所有工作區與系統設定。系統會自動在第一個工作區放一個預設主題「世新」（可以刪除）。建立完成後這個頁面就不會再出現，別人無法再建立擁有者。
2. **新增監測項目**：到「後台・管理 → 監測設定」
   - 主題：選「關鍵字」或「主題標籤」，輸入字詞與天數（預設 3 天）
   - 帳號：輸入 `@帳號` 或貼上個人頁網址，選「自己的帳號」或「競品」
3. **抓第一次**：到「抓取與排程」按「立即抓取」。會跳出一個 Chrome 視窗自動搜尋與捲動，約 3–15 分鐘（依主題與帳號數量），跑完視窗自動關閉。頁面上可以看即時紀錄，跑完下方會列出最新 10 篇貼文。
4. **看分析**：回到「前台・分析」各頁。右上角可切換期間（近 7／14／30／90 天）與匯出 Excel。
5. **設定排程**：系統擁有者到「系統設定」調整每日抓取時間（預設 10:30，可設多個，例如 `10:30, 18:00`）。
6. **邀請同事**（選用）：管理員到「成員」新增帳號並指定角色；要讓外部連線見[讓同網路的同事連線](#讓同網路的同事連線)或[用 Cloudflare 臨時網址對外分享](#用-cloudflare-臨時網址對外分享)。

## 日常使用流程

以下是建議的使用節奏，可依需要調整。

**每天（排程抓取完成後，預設 10:30 之後）**
1. **總覽**：看今天有多少新貼文、總互動、負面標記數，以及互動最高的貼文。
2. **負面留言板**：先看「⚠ 高度」，再看「▲ 中度」。每則都附「這則留言 ↗」「看原文 ↗」，點過去 Threads 看上下文再判斷。需要回報的內容可以下載 CSV。
3. **主題監測**：看哪個主題的提及數或互動「↑ 上升」，點進去看熱門貼文。

**發生突發事件時（例如有人爆料、新聞發酵）**
1. 到「立即爬文」，選近 3 或 6 小時，按「立即爬文」，1–5 分鐘就能補抓到最新貼文。
2. 看頁面下方的「最新 10 篇貼文」，標「新」的就是這次抓到的。
3. 到「負面留言板」看這些貼文底下的負面留言。

**每週**
- **帳號比較**：自己與競品的粉絲成長、互動率、一對一比較
- **最佳發文時段**：安排下週的發文時間
- **內容成功模式**：看高互動貼文有什麼共同特徵
- **主題交叉比較**：比較不同主題的討論量與互動分布

**每月**
- 右上角「匯出 Excel 報表」，選近 30 天，作為月報或會議資料。

**定期維護**
- 「抓取與排程」的抓取紀錄如果常出現「被導向登入頁」「一篇都沒掃到」，代表被 Threads 限制或改版，見[疑難排解](#疑難排解)。
- 負面留言板漏抓或誤抓時，到「系統設定 → 分析字典」補詞，再按「重新分析全部」。

## 功能說明（前台・分析）

所有分析頁都以「目前選擇的工作區」與右上角的「期間」為範圍。工作區看得到的貼文 = 被該工作區主題抓到的貼文 ∪ 該工作區監測帳號發的貼文。

### 總覽
- 指標卡：貼文數、總互動、平均／中位互動、總瀏覽、已抓留言數（正／中／負）、負面標記數
- 每日新貼文（依發布日，台灣時間）
- 每日留言情緒（正面／中性／負面堆疊）
- 互動最高的 5 篇貼文
- 需要注意的留言：含負面關鍵字或判斷為負面的前 8 則，依按讚數排序；「看原文 ↗」用新分頁直接開 Threads 原貼文，另有連結到負面留言板看全部
- 負面關鍵字出現次數排行
- 最近一次抓取摘要

### 負面留言板
把可能是負面的留言（也可切換成貼文或兩者）盡量找出來，寧可多抓、由人判斷。每則會標出命中的訊號並以底色標記，附「這則留言 ↗」「看原文 ↗」（Threads 原文）與系統內詳情連結。

| 訊號類別 | 權重 | 例子 |
|---|---|---|
| 輿情 | 3 | 性騷、霸凌、歧視、申訴、提告、爆料、超收、欠薪、停招 |
| 強烈負評、粗話 | 2 | 垃圾、廢物、擺爛、靠北、智障、學店、斂財、踢皮球、不公平 |
| 抱怨 | 1 | 失望、傻眼、很貴、選不到、借不到、漏水、很吵、延畢、快跑 |
| 句型 | 1 | 「怎麼…都不…」質問句、「不處理／不回應」、「學費拿去…」、「不要念」勸退 |
| 語氣線索 | 0.5 | 笑死、呵呵、==、⋯⋯、？？、😅🙄😡🤡 |

- 系統設定裡的「負面輿情關鍵字」算輿情級、「負面詞」算抱怨，會一併比對
- 抱怨詞前面接「不、沒、並不」等否定詞就不算（例：「並不後悔」）；輿情級一律算
- 同一段文字被較長的詞命中過就不重複加分（「爛透」算過就不再算「爛」）
- 字典情緒判為負面的內容額外加 1 分；整體偏正面、只有語氣線索的不列入（多半是玩笑）
- 分級：含輿情關鍵字或總分 ≥ 3 → **⚠ 高度**；≥ 2 → **▲ 中度**；其餘 → **● 低度**（建議人工確認）
- 可依來源（主題、帳號）、類型（留言／貼文／全部）、嚴重度、關鍵字篩選，依嚴重度、按讚數或時間排序
- 「最常出現的負面訊號」列出前 24 個常見訊號，點一下只看含該訊號的內容
- 畫面最多列 500 則，下載 CSV 會包含全部
- 內建詞庫在 `server/negative.js` 的 `BUILTIN`，要大幅調整可以直接修改

### 主題監測
- **主題熱度排名**：每個主題的提及數、總互動、平均互動、互動中位數、平均瀏覽、提及趨勢、互動趨勢、負面標記數。點欄位標題可切換排名依據。
- **熱度趨勢**：選定主題的每日提及數與每日互動數（兩張圖、各自一個刻度，不做雙軸）。
- **主題熱門貼文**：選定主題中總互動最高的 10 篇，適合研究爆文結構。

### 主題交叉比較
- 用色塊選擇要比較的主題（最多 8 個），顏色固定跟著主題，不會因排名改變
- 每日提及數、每日互動數折線圖
- **互動分布**：每個主題的貼文落在「0–9／10–99／100–999／1,000 以上」哪個互動級距，分辨「少數爆文」還是「普遍有人互動」
- 數字對照表：提及數、討論佔比、總互動、平均、中位數、平均瀏覽、趨勢

### 貼文成效
- **全部串文成效列表**：發布時間、作者、內文、讚、留言、轉發、分享、總互動、較上次、瀏覽、互動率、留言情緒、負面標記。每欄可排序，點列開啟詳情。
- **來源篩選**：工作區全部、自己的帳號、競品帳號、單一主題、單一帳號；可搜尋內文。
- **貼文互動比較**：勾選 2–5 篇，並排比較讚、留言、轉發、分享。
- 下載 CSV。

### 貼文詳情
- 完整內文、作者、發布時間、所屬主題、情緒與負面標記、Threads 原文連結
- 讚、留言、轉發、分享、瀏覽、每千次瀏覽互動數、互動率
- 互動成長與瀏覽成長曲線（需開啟「重新追蹤已抓過的貼文」且至少抓兩次）
- 留言列表：作者、時間、讚數、「原作者說讚」、情緒、負面關鍵字；可篩選「負面關鍵字／負面／正面／中性」

### 瀏覽分析
- 有瀏覽資料的貼文數、瀏覽中位數、每千次瀏覽互動數（中位）
- **瀏覽 × 互動散佈圖**（橫軸對數刻度）：右下角＝看的人多但不太互動
- 每篇貼文的曝光判斷：曝光與互動俱佳／高曝光低互動／曝光偏低／一般（定義見[指標與演算法定義](#指標與演算法定義)）

### 帳號比較
- **帳號總覽**：粉絲數、期間粉絲成長、成長率、每日成長、貼文數、每週發文、平均互動、互動中位數、互動率、平均瀏覽、最佳貼文
- **粉絲成長速度**：各帳號粉絲數量級不同，畫「相對第一筆紀錄的成長 %」，所有帳號共用一個刻度才能比較動能
- **一對一比較**：選兩個帳號，逐項比較並標出哪一方較高；附每週平均互動與每週發文數圖

### 最佳發文時段
- 星期 × 3 小時時段的熱力圖，格內顯示平均互動與篇數，顏色越深平均互動越高
- 建議發文時段：只列出至少 2 篇貼文的時段，依互動**中位數**排序（避免單篇爆文把整格拉高）
- 預設來源是「自己的帳號」（有設定的話）；期間至少取近 30 天

### 內容成功模式
- 把貼文依總互動排序，前 25% 當「高成效」，與其他貼文比較 11 項內容特徵：附圖片或影片、附影片、含問句、使用表情符號、有主題標籤、標記其他帳號、附連結、開頭第一行 15 字內、開頭用數字、含驚嘆號、長文（120 字以上），以及平均字數
- 自動產生差距 15 個百分點以上的洞察句
- 高成效貼文常見詞：在高成效貼文中出現比例明顯較高的雙字詞，可當題材靈感
- 高成效範例貼文
- 至少需要 8 篇有內文的貼文才會分析

## 功能說明（後台・管理）

### 監測設定（編輯以上）
- **主題**：類型（關鍵字／主題標籤）、字詞、天數（1–30）、啟用開關、刪除
  - 關鍵字：Threads 搜尋結果中，內文或主題標籤含該字詞的貼文（不分大小寫）
  - 主題標籤：直接採用 Threads 標籤搜尋（`serp_type=tags`）的結果，輸入時 `#` 可有可無
- **帳號**：帳號、顯示名稱、類型（自己／競品）、目前粉絲數、最後更新時間、啟用開關、刪除
- 刪除主題或帳號不會刪除已抓到的貼文；暫時不想抓可以取消「啟用」

### 立即爬文（編輯以上）
- 馬上抓一次**目前這個工作區**的主題與帳號，**只收近 N 小時內發布、資料庫裡還沒有的貼文**（N 可選 3／6／12／24 小時，預設 6）
- 抓過的一律略過：不重複收錄、不重新點進去，也不回頭更新舊貼文的數字（不受「重新追蹤已抓過的貼文」影響）
- 可選擇要不要順便點進新貼文抓留言與瀏覽數（每篇約多 10 秒）
- 抓取中頁面會顯示即時紀錄，跑完自動更新
- 頁面下方列出這個工作區**最新 10 篇貼文**（依發布時間由新到舊），上次立即爬文新收的標「新」，並註明其中有幾篇是近 N 小時內發布的
- 跟一般抓取共用同一個瀏覽器，同一時間只能有一個抓取在跑

### 抓取與排程
- 「立即抓取」（編輯以上）：所有工作區的主題與帳號會一起抓，同一個字詞或帳號只抓一次
- 即時紀錄：抓取中每 2 秒更新
- **最新 10 篇貼文**：這個工作區已抓到、發布時間最新的 10 篇；最近一次抓取新收的標「新」。點列開啟詳情，每列有「Threads ↗」連結
- 抓取紀錄：每次的開始時間、觸發者（排程／使用者／立即爬文與時間窗）、耗時、狀態、主題收錄數、新貼文、略過重複、帳號數、點進篇數、留言數，可展開完整紀錄
- 顯示下一次排程時間

### 成員（管理員）
- 修改工作區名稱
- 新增成員：輸入已存在的帳號會直接加入；新帳號需設定初始密碼（至少 8 字元），請成員登入後自行修改
- 調整角色、移出成員（不能移出自己）

### 系統設定（系統擁有者）
| 設定 | 預設 | 說明 |
|---|---|---|
| 啟用每日排程 | 開 | |
| 排程時間 | `10:30` | 多個用逗號分隔，使用這台電腦的本地時間 |

## 登入與自動登入

**記住我**
- 登入頁的「記住我」預設勾選：登入狀態保留 **30 天**；只要持續使用，剩不到 15 天時開啟網頁會自動延長回 30 天，所以常用就不會被登出。
- 取消勾選：登入狀態 12 小時，且關閉瀏覽器就失效。適合在公用電腦使用。

**瀏覽器記住密碼、自動登入**
- 登入成功後，Chrome、Edge 會跳出「儲存密碼？」，選「儲存」。
- 之後開啟網頁（或登入過期時），系統會用瀏覽器已儲存的帳密自動登入；若瀏覽器的「自動登入」設定是關閉的，則會自動帶入帳號密碼，按「登入」即可。
- 按「登出」後，瀏覽器不會立刻又自動登入；下次手動登入後才恢復自動登入。
- 自動登入使用瀏覽器的 Credential Management API（Chrome、Edge 支援）；Firefox、Safari 只會自動帶入帳密。
- 密碼只存在瀏覽器自己的密碼管理器，系統不會把密碼寫進網頁或本機儲存空間；伺服器端只存 scrypt 加鹽雜湊。

**其他**
- 登入 cookie 為 HttpOnly、SameSite=Lax；透過 HTTPS（例如 Cloudflare 網址）連線時自動加上 Secure
- 同一帳號連續輸錯 5 次密碼，鎖定 5 分鐘
- 修改或被重設密碼後，該帳號在所有裝置的登入都會失效

## 抓取流程與收錄規則

每次抓取依序做這些事：

1. 開 Chrome，先進 Threads 首頁暖身
2. **主題搜尋**：每個啟用中的主題進 Threads 搜尋頁，捲動收集貼文，直到遇到登入牆
3. **帳號個人頁**：每個啟用中的帳號進個人頁，記錄粉絲數，收集可見貼文（轉發別人的貼文不算）
4. **逐篇點進貼文頁**：取瀏覽數、最新互動數與留言（排除頁面下方的「相關串文」）
5. 關閉瀏覽器，寫入抓取紀錄

每一步之間會隨機停頓幾秒，模擬一般瀏覽節奏，降低被限制的機會。

### 收錄規則（預設）

- **已經抓過的貼文不重抓，也不再點進去。** 同一篇如果也符合別的主題，只在資料庫補上主題標記，不會重新連線。
- **主題搜尋的新貼文：今天有就只收今天的；今天沒有，才收近 N 天的**（N＝該主題設定的「天數」，預設 3）。「今天」以台灣時間計算。
  - 例：9/14 搜尋到 3 篇 9/14 的新貼文、2 篇 9/13 的新貼文 → 只收 9/14 的 3 篇
  - 例：9/15 搜尋不到 9/15 的新貼文、但有 9/13、9/14 各 1 篇還沒收過 → 收這 2 篇
- **帳號的粉絲數每次都會記錄**（粉絲數不是貼文，不受上面規則影響），才看得出成長速度。
- 抓取紀錄會顯示每個主題「符合幾篇、已抓過略過幾篇、最後收了哪幾篇」。

### 重新追蹤已抓過的貼文（選用）

在「系統設定」打開後：每次抓取會回頭更新已抓過貼文的讚數、留言與瀏覽數（近「追蹤天數」內的貼文），這樣「貼文詳情」的互動成長曲線、貼文列表的「較上次」欄才會有資料。代價是每次抓取時間變長、也比較容易被 Threads 限制。

### 立即爬文的收錄規則

- 只抓發起的那個工作區（一般抓取是所有工作區一起抓）
- 時間窗是「現在往回推 N 小時」，不套用「今天優先」規則
- 資料庫裡已經有的貼文直接略過（只補上主題標記），只點進這次新抓到的貼文
- 這次新收的貼文代碼會記在抓取紀錄裡，頁面上據此標「新」
- 訪客模式的搜尋結果不照時間排序、也沒有「最新」分頁（`filter=recent` 參數會被忽略），所以是先收集可見的貼文再依發布時間篩選；討論量大的主題可能漏抓近幾小時的貼文，[帶登入狀態](#使用登入狀態提高抓取量選用)會切到「最新」分頁，準很多

## 指標與演算法定義

| 指標 | 定義 |
|---|---|
| 總互動 | 讚 ＋ 留言 ＋ 轉發 ＋ 分享 |
| 平均互動 | 總互動 ÷ 貼文數 |
| 互動中位數 | 所有貼文互動數的中位數；與平均一起看，避免被少數爆文誤導 |
| 互動率 | 貼文總互動 ÷ 作者粉絲數 × 100%（只有監測清單中的帳號有粉絲數）；帳號互動率＝平均互動 ÷ 粉絲數 |
| 每千次瀏覽互動 | 總互動 ÷ 瀏覽數 × 1000 |
| 提及數 | 期間內被該主題收錄的貼文數 |
| 討論佔比 | 該主題提及數 ÷ 所有選取主題的提及數 |
| 較上次 | 最新一筆互動快照 − 前一筆快照 |
| 期間粉絲成長 | 期間內最後一筆粉絲快照 − 第一筆（少於兩筆顯示「—」） |
| 每日成長 | 期間粉絲成長 ÷ 兩筆快照相隔天數 |
| 每週發文 | 期間貼文數 ÷（期間天數 ÷ 7） |

**熱度趨勢**：把「開始監測以來」的期間切成前後兩半，比較後半與前半的提及數（或互動數）：
- 變化 ≥ +20% → 上升；≤ −20% → 下降；其他 → 持平
- 前半為 0、後半有資料 → 上升（新出現）
- 開始監測後可比較的時間不足 4 天 → 資料累積中

**曝光判斷**（以期間內有瀏覽資料的貼文為母體）：
- 瀏覽 < 瀏覽中位數 × 0.5 → 曝光偏低
- 每千次瀏覽互動 < 其中位數 × 0.5 → 高曝光低互動
- 瀏覽 ≥ 中位數 且 每千次瀏覽互動 ≥ 中位數 → 曝光與互動俱佳
- 其他 → 一般

**情緒判斷**（字典式，可在系統設定調整）：
- 每出現一個正面詞 +1；正面詞前一個字是「不、沒、別、無、非」時改為 −1（例如「不喜歡」）
- 出現負面詞或負面輿情關鍵字，每個不同的詞 −1
- 總分 > 0 正面、< 0 負面、= 0 中性
- 出現任何負面輿情關鍵字（預設：性騷、性侵、偷拍、霸凌、歧視、爆料、申訴、抗議、停招、退場、詐騙、漏水、竊盜、超收、提告、地檢署、黑箱、欠薪、資遣、裁員、性平）就標 ⚠

**負面留言板分級**：見[負面留言板](#負面留言板)。

**最佳發文時段**：依發文時間（台灣）把貼文分到「星期 × 3 小時」共 56 格，計算每格平均與中位互動；建議時段取篇數 ≥ 2 的格子中中位數最高的前三名。

**內容成功模式**：依總互動排序，前 25%（至少 2 篇）為高成效組，其餘為對照組，比較各特徵在兩組的出現比例；差距 ≥ 15 個百分點產生洞察句。常見詞以雙字漢字詞計算「在幾成貼文中出現」，保留在高成效組出現 ≥ 2 次且比例高於對照組者。

## 資料來源的限制

這套系統讀的是 Threads 對**未登入訪客**公開顯示的內容，實測限制如下：

| 項目 | 訪客模式實測 |
|---|---|
| 每個主題搜尋 | 約 5–12 篇就遇到登入牆 |
| 每個帳號個人頁 | 約 10 篇 |
| 每篇貼文留言 | 約 25 則 |
| 搜尋排序 | 不照時間排序（沒有「最新」分頁），會混入較舊的貼文 |
| 瀏覽數 | 只能在貼文頁讀到，而且部分貼文（多半是互動極少的）不顯示「次瀏覽」 |

因此所有統計都是「可見範圍內」的數字，不是完整母體，頁面上也會標示。每天持續抓取，資料會逐日累積，趨勢與最佳時段通常要跑一兩週才有參考價值。

其他：
- Threads 若改版，爬蟲的 DOM 判讀可能失效（抓不到貼文或數字），需要調整 `server/crawler.js`
- 頻繁抓取可能被 Threads 暫時限制，建議每天 1–2 次排程，突發事件再用立即爬文
- 情緒判斷與負面留言板都是字詞比對，無法完全理解反諷與語境；負面留言板刻意多抓，低度的內容建議人工確認

## 使用登入狀態提高抓取量（選用）

如果把 Playwright 的登入狀態檔放在 `data/auth_state.json`，爬蟲會帶著登入狀態抓，搜尋會切到「最新」分頁、也不會遇到登入牆，數量會多很多。

產生方式（**登入動作由你自己在瀏覽器中完成，系統不保存帳號密碼**）：

```bash
npx playwright codegen --channel=chrome --save-storage=data/auth_state.json https://www.threads.com/login
```

在跳出的瀏覽器中登入 Threads，登入完成後關閉視窗，檔案就會存好。下一次抓取的紀錄會顯示「使用 data/auth_state.json 的登入狀態」。

注意：
- `auth_state.json` 等同你的登入 cookie，**不要分享、不要上傳**（`data/` 已在 `.gitignore`）
- 建議使用專門用來監測的帳號
- 登入狀態過期後重新產生即可
- 使用登入狀態自動化瀏覽可能違反 Threads 使用條款，請自行評估

## 用 Cloudflare 臨時網址對外分享

不需要 Cloudflare 帳號、不需要網域，就能產生一個 `https://xxxx.trycloudflare.com` 的公開網址，讓外部的人連進這台電腦的系統。

1. 安裝 cloudflared（Windows 可用 `winget install Cloudflare.cloudflared`）
2. 伺服器照常啟動（維持預設的 `127.0.0.1` 即可，cloudflared 在本機轉接）
3. 執行：

```bash
cloudflared tunnel --no-autoupdate --url http://127.0.0.1:3900
```

輸出中會出現一行 `https://隨機名稱.trycloudflare.com`，就是公開網址。

注意：
- **網址是隨機的**：cloudflared 一停（關閉、重開機）網址就失效，重新執行會拿到新網址；只要 cloudflared 不停，網址就不變
- 只重啟伺服器（例如更新程式碼後）不影響網址
- 臨時通道沒有可用時間保證，不適合長期正式服務
- 網址是公開的：任何拿到網址的人都能看到登入頁，請確保所有帳號都用強密碼
- 經由這個網址連線是 HTTPS，登入 cookie 會自動加上 Secure

要**固定不變的網址**，需要自己的 Cloudflare 帳號與一個交給 Cloudflare 管理 DNS 的網域，改用具名通道：

```bash
cloudflared tunnel login                                   # 瀏覽器登入 Cloudflare 並選網域
cloudflared tunnel create threads-monitor                  # 建立具名通道
cloudflared tunnel route dns threads-monitor threads.example.com
cloudflared tunnel run --url http://127.0.0.1:3900 threads-monitor
```

## 背景執行與開機啟動

`npm start` 開在終端機裡，關掉終端機伺服器就會停。要讓伺服器與 Cloudflare 通道在背景一直跑（Windows PowerShell，把路徑換成實際位置）：

```powershell
$root = "C:\path\to\threads_monitor"
$logs = "$root\data\logs"; New-Item -ItemType Directory -Force $logs | Out-Null

# 伺服器
Start-Process node -ArgumentList "--no-warnings", "server/index.js" -WorkingDirectory $root -WindowStyle Hidden `
  -RedirectStandardOutput "$logs\server.out.log" -RedirectStandardError "$logs\server.err.log"

# Cloudflare 臨時通道（選用）
Start-Process cloudflared -ArgumentList "tunnel", "--no-autoupdate", "--url", "http://127.0.0.1:3900", "--logfile", "$logs\cloudflared.log" -WindowStyle Hidden

# 查目前的公開網址
Select-String -Path "$logs\cloudflared.log" -Pattern 'https://[a-z0-9-]+\.trycloudflare\.com' | Select-Object -First 1
```

常用操作：

| 動作 | 指令 |
|---|---|
| 只重啟伺服器（網址不變） | `Stop-Process -Id (Get-NetTCPConnection -LocalPort 3900 -State Listen).OwningProcess`，再執行上面的「伺服器」那行 |
| 停止通道（網址會失效） | `Stop-Process -Name cloudflared` |
| 確認伺服器在跑 | 瀏覽 http://127.0.0.1:3900/api/setup-status |
| 看伺服器錯誤 | `data\logs\server.err.log` |

**開機自動啟動**（選用）：把上面的指令存成 `start-threads-monitor.ps1`，在「Windows 工作排程器」建立一個「登入時」觸發的工作執行它；或在 `shell:startup` 資料夾放一個執行它的捷徑。開機後通道會是新網址，可以從 `data\logs\cloudflared.log` 查到。

- 有變更才 commit，訊息為「自動備份 YYYY-MM-DD HH:mm」；沒有變更就略過
- 推送前會掃描 GitHub token、API key、私鑰等明顯的密鑰，發現就停止並記錄
- `data/`（資料庫、紀錄、登入狀態）在 `.gitignore` 裡，不會被推上去
- 推送使用 gh 已登入、且名稱與 `origin` 擁有者相同的帳號憑證（例如 `ymlin520`），不會切換 gh 的預設帳號
- 當時電腦關機或沒登入的話，下次開機登入後補跑一次
- 紀錄在 `data/logs/auto-push.log`
- 執行時可能短暫閃一下命令列視窗，屬正常現象
- 注意：它會把當時所有未提交的變更一起推上去，改到一半的程式碼也會被推

手動執行：

```bash
node scripts/auto-push.mjs            # 實際 commit 並推送
node scripts/auto-push.mjs --dry-run  # 只檢查，不 commit 也不推
```

在新電腦建立排程（PowerShell，把路徑換成實際位置；需先 `gh auth login` 登入 repo 擁有者的帳號）：

```powershell
$root = "C:\path\to\threads_monitor"
$action = New-ScheduledTaskAction -Execute (Get-Command node).Source -Argument "`"$root\scripts\auto-push.mjs`"" -WorkingDirectory $root
$trigger = New-ScheduledTaskTrigger -Daily -At "17:00"
$settings = New-ScheduledTaskSettingsSet -StartWhenAvailable -ExecutionTimeLimit (New-TimeSpan -Minutes 10)
Register-ScheduledTask -TaskName "threads-monitor-auto-push" -Action $action -Trigger $trigger -Settings $settings
```

暫停：`Disable-ScheduledTask -TaskName threads-monitor-auto-push`；恢復：`Enable-ScheduledTask -TaskName threads-monitor-auto-push`；移除：`Unregister-ScheduledTask -TaskName threads-monitor-auto-push`

## 備份、搬移與重設

- **備份**：停止伺服器後複製 `data/threads.db`（若有 `threads.db-wal`、`threads.db-shm` 一併複製）
- **搬到新電腦**：在新電腦 `git clone`、`npm install`，再把 `data/` 整個資料夾複製過去
- **忘記系統擁有者密碼**：若還有其他系統擁有者可從「系統設定 → 所有使用者」重設；否則需用 SQLite 工具修改 `users` 表
- **全部重來**：停止伺服器、刪除 `data/threads.db*`，重新啟動會回到首次設定
- 程式碼每天 17:00 自動推上 GitHub，但**資料庫不會**，資料請另外備份

## 常見問題

**為什麼每個主題只抓到幾篇？**
訪客模式下，Threads 捲到約 5–12 篇就會出現登入牆。每天持續抓，資料會逐日累積；要一次抓更多，見[使用登入狀態提高抓取量](#使用登入狀態提高抓取量選用)。

**總覽的「需要注意的留言」和「負面留言板」差在哪？**
總覽只列字典判為負面或含輿情關鍵字的前 8 則；負面留言板用更多訊號（粗話、抱怨、質問句、勸退、反諷語氣、負面表情）、分三級、列出全部，也可以篩選與下載。

**抓過的貼文，讚數還會更新嗎？**
預設不會（抓過的不重抓）。要追蹤成長，到「系統設定」打開「重新追蹤已抓過的貼文」。

**為什麼有些貼文沒有瀏覽數？**
瀏覽數只有點進貼文頁才讀得到，每次點進有篇數上限；而且部分互動極少的貼文 Threads 不顯示瀏覽數。

**負面留言板抓錯或漏抓怎麼辦？**
到「系統設定 → 分析字典」：嚴重的詞加進「負面輿情關鍵字」（算高度），一般抱怨詞加進「負面詞」，存檔後負面留言板立即生效；總覽與報表的情緒要按「重新分析全部」。常被誤抓的詞可以改 `server/negative.js` 的內建詞庫。

**立即抓取和立即爬文該用哪個？**
剛新增主題或帳號、想馬上有資料，用立即抓取；突發事件只想補最新幾小時，用立即爬文（快很多）。詳見[比較表](#立即抓取立即爬文與每日排程的差別)。

**兩個人可以同時按抓取嗎？**
不行，同一時間只能有一個抓取；進行中時按鈕會停用，頁面會顯示是誰在抓、抓到哪裡。

**資料會保存多久？**
永久保存在 `data/threads.db`，右上角的「期間」只影響顯示範圍。

**可以不要跳出 Chrome 視窗嗎？**
系統設定可開「背景執行」，但 Threads 比較容易擋無視窗的瀏覽器，建議維持關閉。

**Cloudflare 網址怎麼又變了？**
臨時網址在 cloudflared 重新啟動（包括電腦重開機）後一定會變。查新網址見[背景執行與開機啟動](#背景執行與開機啟動)；要固定網址需改用具名通道。

## 疑難排解

| 狀況 | 原因與處理 |
|---|---|
| `Error: No such built-in module: node:sqlite` | Node 版本太舊，請升級到 22.13 以上 |
| 抓取失敗：`browserType.launch: Chromium distribution 'chrome' is not found` | 沒有安裝 Chrome，到系統設定把瀏覽器改成 Edge |
| 抓取紀錄顯示「一篇都沒掃到」「被導向登入頁」 | 被 Threads 限制或 Threads 改版；隔一段時間再試、降低抓取頻率，或改用登入狀態 |
| 「讀不到粉絲數」 | 帳號不存在、是私人帳號，或輸入錯誤 |
| 瀏覽分析沒有資料 | 貼文瀏覽量太低 Threads 不公開顯示，或還沒被點進去（每次點進有上限） |
| 互動成長曲線一直是「至少要抓兩次」 | 預設不重抓舊貼文；到系統設定打開「重新追蹤已抓過的貼文」 |
| 趨勢一直顯示「資料累積中」 | 開始監測不到 4 天，持續抓取即可 |
| 排程沒有執行 | 伺服器要開著；確認系統設定已啟用排程、時間格式為 `HH:MM` |
| 立即爬文按鈕不能按 | 有其他抓取正在進行、工作區沒有啟用中的主題或帳號，或權限不足（需編輯以上） |
| 立即爬文新收 0 篇 | 近 N 小時真的沒有新貼文，或都已經抓過；可放寬時間範圍 |
| Cloudflare 網址打不開 | cloudflared 或伺服器停了（重開機、被關閉）；依[背景執行](#背景執行與開機啟動)重新啟動，通道重開後網址會變 |
| 網址列顯示「不安全」 | 用 `http://` 開了 trycloudflare 網址，請改用 `https://` |
| 瀏覽器沒有跳出「儲存密碼」 | 瀏覽器的密碼管理功能被關閉或在無痕模式；可到瀏覽器設定手動新增 |
| 一直自動登入成另一個帳號 | 先按「登出」（會暫停自動登入），再用想要的帳號登入並儲存密碼 |
| 常被登出 | 登入時沒勾「記住我」（12 小時、關瀏覽器就失效），或密碼被修改／重設 |
| 自動推送沒有推上去 | 看 `data/logs/auto-push.log`；常見原因是 gh 沒登入 repo 擁有者帳號、偵測到疑似密鑰、網路中斷 |
| 啟動時出現 `ExperimentalWarning: SQLite` | `npm start` 已加 `--no-warnings`；直接用 node 執行時的提示可忽略 |
| 抓取紀錄停在「中斷」 | 抓取途中伺服器被關閉，重新抓一次即可 |

## 安全性說明

- 預設只允許本機連線；開放區網時沒有 HTTPS，請只在信任的網路使用
- 使用 Cloudflare 臨時網址時，登入頁對外公開：所有帳號請用強密碼，不需要時就停止通道
- 密碼以 scrypt 加鹽雜湊儲存；session 為 HttpOnly、SameSite=Lax cookie，經 HTTPS 連線時加上 Secure
- 同一帳號連錯 5 次密碼鎖定 5 分鐘；首次設定完成後無法再建立系統擁有者
- 在公用電腦登入請取消「記住我」，並且不要讓瀏覽器儲存密碼
- `data/`（資料庫、登入狀態檔、紀錄）已排除在版控之外，請勿上傳；自動推送前也會掃描密鑰
- 抓取的是公開內容，但仍包含一般使用者的帳號與留言；請依所在單位的個資與研究倫理規範使用與保存
